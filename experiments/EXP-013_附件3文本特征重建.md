# EXP-013 附件3文本特征重建

## 问题

附件2同时提供 `text(50×768)` 和 `text_bert(3×50)`，附件3仅提供 `text_bert`。直接复用附件2的数据读取器会发生 `KeyError: text`。必须先证明能否从 `text_bert` 精确重建训练时使用的768维特征。

## 方法

使用本地 `bert-base-uncased`，输入 `text_bert` 的 token ids、attention mask 和 token type ids，取最后一层 `last_hidden_state`。不使用任何外部情感标签或情感数据集。

```powershell
python prepare_attachment3.py
```

## 全验证集复核结果

| 平均余弦相似度 | 1.000000 |
| 最小余弦相似度 | 0.99999976 |
| 展平Pearson | 0.999999999999 |

## 结论

附件2的 `text` 可由官方 `text_bert` 和标准 `bert-base-uncased` 最后一层近乎逐元素复现。附件3不存在不可恢复的文本特征缺口，后续推理必须先重建 `text`，不能把文本设为零、不能修改模型维度，也不能把附件3误判为文本缺失。

生成的本地特征缓存不含标签，且因 `*.pkl` 被 `.gitignore` 排除而不上传仓库；`summary.json` 保留形状、校验值和 SHA256，合作者可自行重建。

## 标签语义同步审计

连续回归真值满足：`y<0` 为负向、`y=0` 仅为中性、`y>0` 为正向。附件2派生的三分类编码为 `0=负向、1=中性、2=正向`。三个官方划分逐样本完全一致，当前代码直接使用该三分类标签，没有把连续值0并入正向。
